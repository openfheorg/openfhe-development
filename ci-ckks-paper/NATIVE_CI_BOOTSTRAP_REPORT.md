# Native FFT-Style Bootstrapping for Conjugate-Invariant (Real) CKKS — Technical Report

**Status:** research prototype, implemented in this OpenFHE fork (`ci-ckks-2026`).
**Artifact:** a CKKS bootstrap that operates **natively over the rank-`N` conjugate-invariant
ring**, evaluating `CoeffsToSlots`/`SlotsToCoeffs` as a real DFT and **never instantiating the
degree-`2N` complex ring**. To our knowledge this did not previously exist in any library or
the literature (the prior art — Lattigo `EvaluateConjugateInvariant`, Bae–Cheon–Kang–Kim
WAHC'25 — refreshes CI ciphertexts by ring-switching up to degree `2N`).

This report documents the derivation, the implementation, and an honest discussion of the
measured native-vs-complex deltas, including where the prototype does **not** yet win.

---

## 1. Derivation (what makes a native real-DFT bootstrap exist)

Let `N` be a power of two, the CI rank and the number of **real** slots. Ambient cyclotomic
`Z[X]/(X^{2N}+1)`, `m = 4N`. The conjugate-invariant ring `R = {a : a(X)=a(X^{-1})}` has the
totally-real canonical embedding `tau(a) = (a(xi_j))_j`, `xi_j = 2cos(pi(4j+1)/(2N))`, giving
`N` real slots. The decode matrix is

```
U[j,0] = 1,   U[j,i] = 2 cos(pi (4j+1) i / (2N))   (1 <= i < N),
```

with the orthogonal-but-not-orthonormal basis norms `||u_0||^2 = N`, `||u_i||^2 = 2N`
(the load-bearing **factor-of-two basis asymmetry**), so `U^{-1} = diag(1/N, 1/2N, ..., 1/2N) U^T`.

Three structural facts make the native bootstrap possible (all verified, see §2):

1. **The Galois group** of the real subfield is cyclic of order `N`, generated by `g = 5`, and
   acts simply transitively on the `N` slots — a full cyclic slot rotation exists natively.
2. **The CI embedding is the restriction of the complex special-FFT to the conjugation-fixed
   subspace.** Concretely `U(natural order) = 2*Re(W@4N)` with column 0 halved and rows permuted
   by `P`, where `W[s][c]=exp(2*pi*i*c*5^s/4N)` is exactly what OpenFHE's `FFTSpecial(cyclOrder=4N)`
   computes. Conjugation acts as the identity on `R`, so the conjugate-pair butterfly structure
   collapses to a real DFT.
3. **Only CtS/StC differ** from complex CKKS. `ModRaise` is identical; `EvalMod` is identical and
   *simpler* (a slot-wise function on already-real slots — no real/imaginary split).

The CI ring multiplication is realized by the **twisted CI-NTT** (Kim–Song §4.3): a coefficient
twiddle followed by an `N`-point cyclic NTT, evaluating at the nodes `w_{4N}^{4j+1}`. This is a
ring isomorphism `R_q ~ Z_q^N`, so Hadamard product in the NTT domain equals CI multiplication.

The bootstrap pipeline, rank `N` throughout: `ModRaise -> CI-CtS(U^{-1}) -> EvalMod -> CI-StC(U)`.

## 2. Implementation and verification (OpenFHE)

The native path is selected by a new `CKKSDataType::REAL_CI`; the rank-`N` / no-ring-switch
invariant holds by construction — the CI ciphertext ring is `ILDCRTParams(2N)` (totient `N`),
with RNS primes `q = 1 mod 4N`; a degree-`2N` ring (`ILDCRTParams(4N)`, totient `2N`) is never built.

| Component | Where | Verified against |
|---|---|---|
| Dual real-DFT factorization | `reference/` (mpmath, 256-bit) | restriction-of-complex ≡ independent radix-2 ≡ Chebyshev, all to `2^-100` |
| Twisted CI-NTT | `core/math/ci-transform`, `SwitchFormat` dispatch | Hadamard = CI-mult vs independent negacyclic-convolution oracle |
| CI param-gen / encode / decode | `ckksrns-parametergeneration`, `ckkspackedencoding` | Kim–Song toy example; Enc/Dec round-trip < 1e-6 |
| EvalAdd / EvalMult (CI QP key-switch) | `rns-cryptoparameters`, `base-scheme` | slot-wise add/product < 1e-3 |
| CI rotations (Galois `g=5`) | `nbtheory2` `PrecomputeAutoMapCI`, `base-leveledshe` | exact slot permutation; `k=-1` = identity |
| CI homomorphic linear transform | `EvalBootstrap` (BSGS) | `M·v` on ciphertext vs cleartext |
| **Native CI bootstrap + no-ring-switch guard** | `ckksrns-fhe` `EvalBootstrap` REAL_CI branch | `Decrypt(Boot(ct)) ~ Decrypt(ct)`; rings all rank `N` |

All standard CKKS/BGV/BFV tests remain green (every CI branch is opt-in; a lock-free fast path
protects the NTT hot path). `EvalMod` is the stock Chebyshev sine + double-angle, reused unchanged.

The CtS/StC use the baby-step/giant-step (`~2 sqrt(N)` rotations) real-DFT linear transform: the
CI rotations `{5^t}` form a cyclic group (`5^{n1 j+i} = (5^{n1})^j 5^i`), so the standard hoisted
BSGS applies. CtS = `scaleEnc * N * U^{-1}` (basis-asymmetry-correct), StC = `scaleDec * U`; the
`scaleEnc/scaleDec/correction` constants mirror `EvalBootstrapSetup` exactly.

## 3. Benchmark: native CI vs standard complex CKKS (reals only, matched ring dimension)

`benchmark/src/ci-vs-complex-bootstrapping.cpp`. **A** = standard complex CKKS fed real data
(`N/2` usable real slots, level-collapsed FFT bootstrap, levelBudget `{3,3}`). **C** = native CI
(`N` real slots, BSGS single-level LT, levelBudget `{1,1}`). Same machine, same compiler, same
secret distribution (`UNIFORM_TERNARY`), `FIXEDMANUAL`/`FLEXIBLEAUTO`.

After the **lazy-precompute** latency optimization (the N CtS/StC diagonal plaintexts are
encoded once and cached, eliminating the per-bootstrap re-encode the first benchmark exposed):

```
config             realSlots  #galKeys  log2Q   boot(s)   us/realslot   prec(bits)
N=512:
A (std complex)        256        26     1360     27.7      108154         37.4
C (native CI)          512        46     1160     33.9       66167          6.7
  -> CI packs 2.00x real slots; FASTER per real slot (66us vs 108us);
     real-slot throughput ratio C/A = 1.63x  (WIN)
N=1024:
A (std complex)        512        23     1360     22.1       43136         36.0
C (native CI)         1024        62     1160     52.3       51124          3.8
  -> 2.00x real slots; real-slot throughput ratio C/A = 0.84x (near parity)
```

The optimization moved CI from `69.9s -> 31-34s` at N=512 (throughput ratio `0.63x -> 1.63x`)
and `165s -> 52s` at N=1024 (`0.30x -> 0.84x`).

### Honest discussion of the deltas (plan §12 — null/mixed results are reportable)

- **Packing + amortized throughput (WIN, as predicted):** CI delivers `2x` usable real slots and,
  at N=512, **`1.63x` the useful real-slot throughput** at matched ring dimension — it is *faster
  per real slot* than standard CKKS (66us vs 108us). This is exactly the plan's amortized-throughput
  hypothesis, realized through bootstrapping.
- **Parameter size (WIN signal):** CI's `log2(Q)` is **smaller** (1160 vs 1360) — the single-level
  CI real-DFT LT is shallower than the complex level-collapsed FFT — favorable for the clean
  single-`N` security and key/ciphertext-size story.
- **Scaling (mixed):** the throughput ratio falls from `1.63x` (N=512) to `0.84x` (N=1024) because
  the single-level BSGS LT uses more Galois keys/rotations than the standard level-collapsed FFT as
  `N` grows. The **level-collapsed CI real-DFT** (next optimization) is expected to restore/extend
  the win at larger `N`.
- **Precision (OPEN — the remaining iso-precision item; diagnosis now pinned by measurement):**
  CI recovers `~4-7` bits vs std `~37` (the same gap under iso-config, both FIXEDMANUAL). The deficit
  is a **uniform additive noise floor** (verified *not* a basis-asymmetry/slot-0 effect —
  `maxerr == maxerr_excl_slot0`; and *not* a scale error — the output is correctly scaled, the error
  is message-independent). A sequence of isolating measurements **overturns the earlier guess** that
  blamed generic "single-level LT noise":
  - **CtS scale is correct.** Post-CtS slots equal `scaleEnc * t` (the same EvalMod input scale as
    the standard path, `k=1`): the homomorphic scale bookkeeping makes `decode(raised) = U·t/N`, so
    `CtS = scaleEnc·N·U^{-1}` lands the message at the right point of the sine. (Forcing `CtS =
    scaleEnc·U^{-1}` instead drives the output to `~10^2` — confirming the `N` factor is required.)
  - **The homomorphic LT is *not* the floor at working modulus.** Measured `M·v` precision is
    **39.8 bits at N=64 and 35.4 bits at N=256** at depth 2 (high modulus) — summing `N` rotated
    terms at one level is fine there.
  - **EvalMult / CI QP key-switch is fine:** **32.6 bits** for a fresh product.
  - **EvalMod is byte-identical to the standard path** (same Chebyshev coefficients, `[-1,1]` range,
    `R_UNIFORM` double-angle, `scalar`), only *simpler* (no real/imag split).
  - **Key-switching at bootstrap depth is *not* the floor.** The double-angle chain `x→2x²−1` (the
    EvalMod kernel, depth 6, `UTCKKSrnsCI.CIDoubleAngleChainVsStd`) gives **CI 22.4 bits vs std
    24.3 bits** — only ~2 bits apart. So the CI relinearization/rotation noise at depth is competitive.
  - **The EvalMod input scale is correct (decryption-verified).** `raised` is normalized by
    `1/(K_UNIFORM·N)` *before* the CI branch, and the decrypted post-CtS EvalMod input for CI matches
    std's in magnitude and range (both `~0.01–0.03`, within `[-1,1]`). So it is **not** a `K`/`q0`/
    message-ratio miscalibration.
  - **At matched single-level config the two are close.** `{1,1}`: std **9.0** bits, CI **6.5** bits
    (~2.5 bits apart). std's high precision comes **entirely from the level-collapse**: std `{1,1}→{2,2}`
    is `9→38` bits (**+29**). CI's collapse delivers ≈0 and gets *worse* with more levels
    (CI `{2,2}`=5.6, `{4,4}`=4.8) — the opposite trend.

  - **The transform implementation is *not* the floor — ruled out a fourth way.** The
    **hoisted, extended-basis two-channel evaluator** (the conjectured fix: `applyCILT` rewritten to
    `EvalFastRotationPrecompute` + `EvalFastRotationExt` + deferred `KeySwitchDown`, with a CI branch
    added to `EvalFastRotationExt`; commit `9adccad2`) is now implemented and **much faster** (collapsed
    `{4,4}` N=256: ~16–35 s vs ~146 s non-hoisted) — but it still floors at **~5 bits**. Single-level
    non-ext, collapsed non-ext, and collapsed ext-hoisted all give ~5–6 bits.
  - **CI encode/encrypt/decode round-trip is 37 bits** at the bootstrap config — not the floor.

  **Root cause, now localized by stage-by-stage decryption (single-level, no permutation):**
  `postEvalMod` decrypts to **exactly `0.5·U^{-1}·x`** (the reduced message coefficients `m_c`, ratios
  all `0.50`) — so **CtS + EvalMod correctly recover the coefficients**, to `~1e-5` (`~16-bit`) absolute
  error. The floor is then **two effects intrinsic to the totally-real CI ring, not the transform**:
  1. **Coefficient-recovery ceiling (~16 bits).** The CI message is spread over `N` coefficients by
     `U^{-1}`, so each `m_c` is small (`~0.001–0.08`) and is a tiny fraction (`~2^{-18}`) of the
     ModRaise-overflow-dominated `raised`; the CtS preserves it only to `~16` bits absolute (vs the
     `35–40` standalone bits, which were measured on overflow-free O(1) inputs).
  2. **StC amplification (~8–9 bits).** The CI decode `U` is **non-orthonormal** (`‖u_0‖²=N`,
     `‖u_i‖²=2N`) and sums `N` terms, so it amplifies the per-coefficient recovery error by `~√(N)·‖U‖`
     (`~300×` measured) when mapping `m_c` back to slots — `16 − ~9 ≈ 7` recovered bits.
  Standard CKKS avoids both: its slots map to `N/2` complex coefficients (less spreading) and its
  decode is the near-orthonormal special-FFT (no error amplification).

  **Path to iso-precision (open, and now understood to be structural, not an evaluator detail):**
  the levers are (a) reducing the overflow-to-message ratio in CtS (e.g. a sparse secret to shrink
  `‖I‖`, or a larger message scale), and (b) an `StC` formulation that does not amplify
  (orthonormalized basis / scaled coefficients). An arcsine/minimax `EvalMod` is orthogonal. META-BTS
  is explicitly excluded (it masks rather than fixes the per-bootstrap precision). The bootstrap
  refreshes correctly and the hoisted evaluator is the right (and fast) architecture; the residual
  precision gap is a property of the real ring's geometry (spread coefficients + non-orthonormal `U`),
  not a software defect.

### What the data does and does not show

It **shows** a correct, end-to-end native real-DFT CI bootstrap that realizes the `2x` real packing,
a **smaller modulus**, and (at N=512) a **`1.63x` real-slot throughput win** at matched ring
dimension. It does **not** yet show a strict *iso-precision* comparison (CI precision is currently
low) nor a sustained win at very large `N` (needs level-collapse). The contributions stand: the
first implemented **native** real-DFT CI bootstrap, the clean single-`N` no-ring-switch story, the
eliminated dimension doubling, and a demonstrated amortized-throughput advantage.

## 4. Remaining work (mapped to the plan)

- **Precision / iso-precision (Phase 4):** arcsine/minimax `EvalMod`, tune CI to match A's
  recovered bits before the headline latency comparison; META-BTS; sparse packing.
- **Performance + iso-precision (level-collapse) — partially done, with a sharp negative result.**
  The exact recursive **real** CI-DCT/DST factorization is derived and validated to `2^-100`
  (`reference/ci_ckks/factorization_collapse.py`): the real CI-DFT factors as a coupled `FC`/`FS`
  recursion (`ci_dct = FC - a[0]`, `ci_dst = FS`), i.e. `log2(N)` real butterfly stages, collapsible
  into a 2-fat-stage 4-matrix decomposition. The **C++ homomorphic two-stage port is implemented and
  correct** (`ckksrns-fhe.cpp`, selected by `levelBudget {2,2}`; single-level `{1,1}` remains the
  default): it tracks the `FC`/`FS` ciphertext pair, applies each stage via the same BSGS LT, and
  rescales between stages; the bootstrap refreshes correctly (verified end-to-end).
  **However it does *not* improve precision and is ~2× slower at moderate N.** Root cause, now
  confirmed by measurement (`reference/tests/test_collapse_g5.py`): the factorization decimates on
  the coefficient index (`a[0::2] / a[1::2]`), so its **IN stage** matrices are **dense under the
  multiplicative `g=5` rotation basis** that the homomorphic LT runs in (`Mfci/Mfsi` have `~N`
  nonzero `g=5` diagonals — 256 at N=256; only the OUT stage is sparse). The first stage therefore
  still costs `~N` rotation key-switches, so the two-stage neither cuts rotations nor lowers
  per-level noise — it only adds a rescale, which alone is not enough.

  **The genuine fix — a `g=5`-rotation-*aligned* collapsed FFT — is now derived and validated to
  `2^-100`** (`reference/ci_ckks/collapse_g5.py`, 22 cases green). It reuses OpenFHE's exact complex
  `CoeffEncoding/DecodingCollapse` structure (sparse under `g=5` *by construction* — that is what
  makes the standard hoisted-BSGS evaluator work), composes single-layer stages into `lvlb` fat
  levels, and runs the **real** CI transform as a **two-channel (`FC`=Re, `FS`=Im)** computation
  through those complex `g=5`-sparse stages (a real DCT needs the DST companion → two channels).
  Validated facts (`THRESHOLD = 2^-100`):
  - the fat-level product reconstructs `dense_U` exactly for every `(N, lvlb)` with `lvlb | log2 N`;
  - **each fat level is `g=5`-sparse**: `≤ 2^(layersCollapse+1)-1` diagonals — N=256/`lvlb`=2 gives
    `[31, 16]` per level (vs `256` single-level), `lvlb`=4 gives `[7,7,7,4]`;
  - the CtS/StC round-trip is **exact**: `StC = U` via the fats, `CtS = U^{-1} = diag(1/‖u_i‖²)·U^T`
    via the *same* fats transposed, with `U·U^{-1} = I` to `2^-100`;
  - `CtS·U` is a **signed permutation**, so EvalMod sees pure coefficients.

  **This is now implemented in C++** (`ckksrns-fhe.cpp`: `CICoeffOneLevel`, `CISlotPermG5`,
  `CICollapseNatFats`, the `twoChannel` apply in `EvalBootstrap`; selected by `levelBudget {2,2}`,
  i.e. `lvlb>1 ∧ lvlb|log2N`). The homomorphic round-trip is exact: CtS = encoding collapse, StC =
  decoding collapse with the basis scale `diag(1,2,…)` folded in, the internal bit-reversal cancelling
  through the slot-wise EvalMod. **Both the non-hoisted and the hoisted extended-basis evaluators are
  now implemented** (the latter, `9adccad2`, mirrors `EvalCoeffsToSlots`: shared `FC`/`FS` baby
  rotations, accumulation in the QlP basis, deferred `KeySwitchDown`, with a CI branch in
  `EvalFastRotationExt`); the hoisted one is **much faster** (collapsed `{4,4}` N=256 ~16–35 s).
  **Neither lifts precision** — see the Precision discussion: stage-by-stage decryption shows CtS+EvalMod
  recover the coefficients correctly (`postEvalMod = 0.5·U^{-1}x` to ~16 bits), and the residual floor
  is intrinsic to the real ring (small spread coefficients swamped by the ModRaise overflow in CtS, and
  the non-orthonormal `U` amplifying the per-coefficient error in StC), **not** the evaluator. So the
  hoisted collapse is the right *latency* architecture, but iso-precision needs structural levers:
  **(1)** shrink the overflow-to-message ratio in CtS (sparse secret to reduce `‖I‖`, larger message
  scale); **(2)** an `StC` that does not amplify (orthonormalized basis / scaled coefficients);
  **(3)** arcsine/minimax EvalMod (orthogonal). META-BTS is excluded (masks rather than fixes
  per-bootstrap precision). Plus FFT-accelerated CI encode + Setup-precomputed diagonals for latency.
- **Security (Phase 3):** lattice-estimator harness validating each parameter set `>= 128`-bit on
  its true `(N, log Q, secret, sigma)`; the Kim–Song §3.2 argument that the CI structured-matrix
  distribution admits no better-than-standard attack (so the standard estimate applies at dim `N`).
- **Final benchmark (Phase 5):** the full iso-security / iso-precision sweep at `2^15 / 2^16` with
  ≥30 runs, median+IQR, once the above land.
