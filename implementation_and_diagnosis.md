# Native Conjugate-Invariant (Real) CKKS Bootstrap — Implementation & Precision Diagnosis

**Branch:** `ci-ckks-2026` (OpenFHE fork) · **Status:** end-to-end native CI bootstrap works and
refreshes correctly; the headline open problem is **recovered precision** (CI ≈ 5–7 bits vs standard
CKKS ≈ 38 bits at iso-config). This document is a complete, evidence-rich record of *what was built*
and *exactly where and why the precision is lost*, written so a fresh planner can design the fix.

The one-line conclusion of the diagnosis: **the precision floor is NOT in the homomorphic linear
transform (CtS/StC), NOT in key-switching, NOT in EvalMod, and NOT in encode/decode — all measured
fine. It is a structural property of the totally-real CI ring: (1) the message, spread over `N`
coefficients by `U^{-1}`, is swamped by the ModRaise overflow inside CtS (coefficient recovery caps
at ~16 bits), and (2) the non-orthonormal CI decode `U` amplifies the per-coefficient error by ~`N`
when StC maps coefficients back to slots.**

---

## 1. Goal and mathematical background

### 1.1 The objective
Build a CKKS bootstrap operating **natively over the rank-`N` conjugate-invariant (CI) ring**
`R = { a ∈ Z[X]/(X^{2N}+1) : a(X) = a(X^{-1}) }`, which has `N` **real** slots (vs `N/2` complex
slots for standard CKKS at the same ring dimension). CtS/StC are evaluated as **real DFTs**; the
degree-`2N` complex ring is **never instantiated** (the "no-ring-switch" invariant, distinguishing
this from the Lattigo `EvaluateConjugateInvariant` / Bae–Cheon–Kang–Kim approach, which ring-switch
up to `2N`). For real workloads this exposes `2×` SIMD width and a single clean `N`-dim LWE security
analysis.

### 1.2 The CI embedding (the load-bearing math)
`N` a power of two, `m = 4N`, nodes `ξ_j = 2cos(π(4j+1)/(2N))`. The **decode** matrix is
```
U[j][0] = 1,   U[j][i] = 2·cos(π(4j+1)i/(2N))    (1 ≤ i < N),   slots = U · coeffs
```
The columns are orthogonal but **not orthonormal**:
```
‖u_0‖² = N,   ‖u_i‖² = 2N  (i ≥ 1)   ⇒   U^T U = diag(N, 2N, …, 2N)
encode = U^{-1} = diag(1/N, 1/2N, …, 1/2N) · U^T
```
This **factor-of-two basis asymmetry** and the non-orthonormality are central to the diagnosis (§7).
A useful derived quantity: the **L∞ row norm** of `U` is `Σ_i |U[j][i]| = 1 + Σ_{i≥1} |2cos(…)| ≈ 1.3·N`
(≈ 330 for `N=256`) — this is the StC error-amplification factor.

Three structural facts make the native bootstrap possible (all verified to `2^-100` in `reference/`):
1. The Galois group of the real subfield is cyclic of order `N`, generated by `g = 5`; rotations are
   `ψ_{5^k}`; conjugation `X→X^{-1}` is the **identity** on `R`.
2. `U` is the **real restriction** of OpenFHE's complex special-FFT at cyclotomic order `4N`:
   `U·coeffs = Re( FFTSpecial_{4N}(Dscale·coeffs) )` reordered by the `g=5` slot permutation,
   `Dscale = diag(1,2,…,2)`.
3. Only CtS/StC differ from standard CKKS; **ModRaise and EvalMod are identical** (EvalMod is even
   *simpler* — a slot-wise function on already-real slots, no real/imag split).

### 1.3 The rank-`N` / no-ring-switch mechanism
`REAL_CI` is a third `CKKSDataType` (`REAL=0, COMPLEX, REAL_CI`). Param-gen sets `n = N`,
generates RNS primes at `nttCyclOrder = 4N` (so `q ≡ 1 mod 4N` for the twisted CI-NTT), and builds
`ILDCRTParams(2N)` ⇒ `RingDimension = totient(2N) = N`. A degree-`2N` ring (`ILDCRTParams(4N)`,
totient `2N`) is **never** built — enforced by a runtime guard + fault-injection test.

## 3. The CI bootstrap pipeline (exact, with the scale chain)

`FHECKKSRNS::EvalBootstrap` (`src/pke/lib/scheme/ckksrns/ckksrns-fhe.cpp:666`). The CI branch is at
line **886** (`if (cc->GetCKKSDataType() == REAL_CI)`). Pipeline:

```
ct (level 0, modulus q0)                                  // input, message m in N real slots
 → ModRaise: reinterpret mod full Q ⇒ coefficients t = m_c + q0·I   (‖I‖∞ ≤ K, the overflow)
 → raised *= pre·(1/(k·N))     [line 875]  k = K_UNIFORM = 512       // normalize EvalMod input to [-1,1]
 → CtS  = scaleEnc·N·U^{-1}    (puts the coefficients t into the slots)
 → EvalChebyshevSeries(coeffs=g_coefficientsUniform, [-1,1])         // sine approx of (t mod q0)
 → ApplyDoubleAngleIterations(R_UNIFORM = 6)
 → MultByIntegerInPlace(scalar)
 → StC  = scaleDec·U           (puts the recovered coefficients back into slots)
```
Constants (CI branch ≈ line 893): `factorBoot = 2^round(log2 qDouble)`,
`scaleEnc = qDouble/factorBoot ≈ 1`, `scaleDec = factorBoot/qDouble ≈ 1`, `scaleEnc·scaleDec = 1`.
`k = K_UNIFORM = 512` and the `1/(k·N)` normalization at line **875** are applied to `raised`
**before** the CI branch — i.e. **shared with the standard path** (so the EvalMod-input scale is
identical to standard CKKS; this was directly verified, §6).

`GetBootstrapDepth(levelBudget, UNIFORM_TERNARY)` allocates the towers; `levelsAfter = 6` in tests.

### 3.1 Why CtS uses `scaleEnc·N·U^{-1}` (the homomorphic scale bookkeeping)
`applyCILT(ct, M)` computes `M·(decoded slots of ct)`. The decoded slots of `raised` equal `U·t/N`
(the `1/N` from the homomorphic scaling), so `CtS = scaleEnc·N·U^{-1}` gives post-CtS slots
`= scaleEnc·t` — the **same EvalMod-input scale as standard CKKS** (`k=1` for UNIFORM_TERNARY at the
`scaleEnc` level; the `K_UNIFORM=512` factor lives in the line-875 normalization). Forcing
`CtS = scaleEnc·U^{-1}` (no `N`) drives the output to `~10^2`, confirming the `N` is required.

## 4. The four CtS/StC transform implementations (all tried; none fix precision)

The CI real-DFT cannot factor into real single-channel radix-2 stages (a real DCT needs the DST
companion), so every multi-level form is a **two-channel** `(FC=Re, FS=Im)` computation:
`newFC = Re·FC − Im·FS`, `newFS = Re·FS + Im·FC`, with `FS` starting at 0 (real input) and `FC`
taken at the end.

1. **Single-level BSGS LT** (`lvlb {1,1}`, `applyCILT` over the dense `U^{-1}`/`U`):
   `ckksrns-fhe.cpp:918`. ~`2√N` rotations at one level. The default/benchmarked path (fastest).
2. **Stride two-stage** (`factorization_collapse.py`): decimates on the *coefficient* index
   (`a[0::2]/a[1::2]`). Validated to `2^-100`, **but its IN-stage matrices are dense under the `g=5`
   rotation** (`Mfci/Mfsi` have `~N` g5-diagonals: 256 at N=256) — so it spent single-level cost per
   stage. Retired.
3. **g=5-aligned collapsed real-DFT** (`56239e7c`): reuses OpenFHE's complex `CoeffEncoding/Decoding
   Collapse` structure (sparse under `g=5` by construction), composes single-layer stages into `lvlb`
   fat levels (`CICollapseNatFats`, `ckksrns-fhe.cpp:205`), runs the 2-channel transform via
   `applyCILT`. **g5-sparse**: N=256/`lvlb`=2 → `[31,16]` diagonals/level (vs 256), `lvlb`=4 →
   `[7,7,7,4]`.
4. **Hoisted, extended-basis 2-channel evaluator** (`9adccad2`, the "real fix"): `applyCILT` rewritten
   to mirror `EvalCoeffsToSlots` — one `EvalFastRotationPrecompute` reused across baby rotations,
   accumulation in the extended `QlP` basis (`EvalMultExt`/`EvalAddExtInPlace`), **deferred
   `KeySwitchDown`** (one ModDown per giant block, vs per rotation). Required a CI branch in
   `LeveledSHECKKSRNS::EvalFastRotationExt` (`ckksrns-leveledshe.cpp:550`): for `REAL_CI` the raw
   Galois element `5^k` is used directly (logical `M=4N`) with `PrecomputeAutoMapCI`. Diagonals are
   CI-encoded in the `QlP` basis via `CKKSPackedEncoding(REAL_CI).Encode()`.

The Python validation of #3/#4 (`reference/ci_ckks/collapse_g5.py`, `reference/tests/test_collapse_g5.py`,
22 cases at `THRESHOLD = 2^-100`) proves: the fat-level product reconstructs `dense_U` exactly; each
fat level is `g=5`-sparse (`≤ 2^(layersCollapse+1)-1` diagonals); and the CtS/StC round-trip is exact
(`StC·diag(w)·CtS = N²·I` to `2^-100`, `CtS·U` = a signed permutation so EvalMod sees pure coefficients).

**Result table (latency + precision, N=256 unless noted):**

| Transform | levelBudget | wall-clock | recovered bits |
|---|---|---|---|
| single-level | {1,1} | ~31–37 s | **6.5–7.3** |
| stride two-stage | {2,2} | ~72 s | 5.6 |
| g5-collapse (non-ext) | {2,2} | ~37 s | 5.6 |
| g5-collapse (non-ext) | {4,4} | ~146 s | 4.8 |
| **g5-collapse (hoisted ext-basis)** | {4,4} | **~16–35 s** | 5.0–5.6 |

The hoisted ext-basis evaluator is **correct and ~4× faster** — but precision is **unchanged**. This
**rules the transform implementation out as the precision floor a fourth way** (the others: standalone
LT, EvalMult, and the standalone double-angle chain are all fine; see §5).

from collapse, and CI does not, is **not** an evaluator/noise-management property — see §7.

## 6. The EvalMod-input scale is correct (decryption-verified)

A debug hook decrypted the post-CtS ciphertext (the EvalMod input) for CI and std on matched configs
(constant and sinusoidal messages):
- std EvalMod input `[0..5]` ≈ `[-0.016, -0.002, -0.002, 0.014, …]`, maxabs `0.027`, within `[-1,1]`.
- CI  EvalMod input `[0..5]` ≈ `[-0.006, -0.016, -0.016, 0.010, …]`, maxabs `0.016`, within `[-1,1]`.

They match in magnitude and range. So the `K`/`q0`/message-ratio normalization is **correct** for CI;
this is **not** a scale-calibration bug. (The decrypted values are quantized to ≈`1/N` in the 8-digit
display — that is the overflow-integer part; the tiny message fraction is below it and *is* recovered,
see §7.)

## 7. Definitive localization — stage-by-stage decryption (the key evidence)

On the **single-level** path (`{1,1}`, **no internal permutation**, so a clean comparison), with
`x[i] = sin(0.05(i+1)) ∈ [-1,1]`, `N=256`, decrypting each stage:

```
expected m_c = U^{-1}·x   [0..7] = 0.00257  0.00346  0.07716  -0.00262  -0.00121  -0.00078  -0.00059  -0.00048
postCtS (EvalMod input)   [0..7] = 0.00391 -0.01172  0.01172  -0.01563   0.01563   0.00977   0.00391  -0.00391   (quantized ~1/N: overflow part)
postEvalMod               [0..7] = 0.00126  0.00174  0.03857  -0.00131  -0.00061  -0.00040  -0.00032  -0.00023
```

**`postEvalMod` = exactly `0.5 · U^{-1}·x`** — the ratios are `0.00126/0.00257 = 0.49`,
`0.00174/0.00346 = 0.50`, `0.03857/0.07716 = 0.50`, `-0.00131/-0.00262 = 0.50`, … all `0.50`. (The
`0.5` is a scale convention absorbed downstream; the final output magnitude is correct,
`got 0.054` vs `want 0.050`.)

**Therefore CtS + EvalMod correctly recover the message coefficients.** The recovery error is
`postEvalMod − 0.5·m_c ≈ [−2.2e-5, +8e-6, −8e-6, +4e-6, −8e-6, −9e-6, −2.2e-5, +1.7e-5]` — i.e.
**~`1e-5` ≈ `2^-16.6` absolute error** on the recovered coefficients. The final slot precision is
**7.3 bits** (maxerr `0.0065` on a message in `[-1,1]`).

### 7.1 The two intrinsic effects that produce the floor

**(A) Coefficient-recovery ceiling ≈ 16 bits — overflow swamps the small CI coefficients in CtS.**
The CI message is spread over `N` coefficients by `U^{-1}`, so each `m_c` is small (`~0.001–0.08`).
In `raised`, the message sits on top of the ModRaise overflow `q0·I`:
`|q0·I| / |m_c·Δ| = (q0/Δ)·|I|/|m_c| ≈ 2^10 · 16 / 0.04 ≈ 2^18.6` — the message is `~2^{-18}` of the
overflow-dominated input. CtS (the LT) preserves it to roughly `40 − 18.6 ≈ 21` bits relative,
measured at `~16` bits absolute. (The `35–40`-bit standalone LT number was measured on overflow-free
`O(1)` inputs — not representative of the bootstrap regime.)

**(B) StC amplifies the per-coefficient error by ≈ `N`.** StC maps coefficients back to slots via
`U` (`slots = U·coeffs`). The error in a slot is `Σ_i U[j][i]·ε_i`, bounded by the **L∞ row norm**
`‖U‖_∞ ≈ 1.3·N ≈ 330` for N=256. Measured: `postEvalMod` error `~1e-5` → final slot error `~0.0065`,
a `~300–650×` amplification — consistent with `‖U‖_∞`. This is **inherent to the non-orthonormal CI
decode** (`‖u_i‖² = 2N`, summing `N` `2cos` terms).

So: `16 (recovery) − ~9 (StC amplification, log2 ≈ N) ≈ 7` recovered slot bits. **Both numbers match
the observed ~7-bit single-level / ~5-bit collapsed floor.**

### 7.2 Why standard CKKS does not suffer this (and the open sub-question)
Standard CKKS at the *same* parameters and *same* secret distribution gets 38 bits. Its slots map to
`N/2` *complex* coefficients (less spreading, larger per-coefficient magnitude) and its decode is the
**near-orthonormal** complex special-FFT (no `~N` error amplification). Decomposing 38 bits:
std recovers coefficients to `~46` bits and its (orthonormal) StC loses `~log2(N) ≈ 8` to give 38;
CI recovers to `~16` bits and its (non-orthonormal) StC loses `~log2(N) ≈ 8` to give `~7`.

**Open sub-question for the planner:** the StC amplification factor (`~N`) is *roughly the same* for
both (both decode matrices sum `N` terms), so the dominant gap is the **coefficient-recovery
difference: CI ~16 bits vs std ~46 bits**, despite identical overflow `‖I‖` and comparable coefficient
magnitudes. Hypotheses to test (not yet resolved):
- The standard fully-packed path uses the **conjugation trick** (it forms `ctxtEnc` and
  `ctxtEncI = (ctxtEnc − conj)/i`, EvalMods both, recombines) — effectively two real channels carrying
  the full complex message. The CI ring has no conjugation (it is the identity), so CI uses a single
  real channel. Whether this halves effective precision / changes the overflow interaction is untested.
- Possible difference in how the message energy concentrates: complex `N/2`-slot packing may place the
  message at a higher per-coefficient magnitude relative to the overflow than real `N`-slot packing.

## 8. Structural levers for a fix (none are evaluator/software details)

Given §7, iso-precision requires changing the **ring geometry / parameter regime**, not the evaluator:

1. **Reduce the overflow-to-message ratio in CtS** (attacks effect A, the dominant gap):
   - **Sparse secret** (`SPARSE_TERNARY`/`SPARSE_ENCAPSULATED`): smaller Hamming weight ⇒ smaller
     `‖I‖` ⇒ message is a larger fraction of `raised` ⇒ higher coefficient-recovery. The CI branch
     currently **throws** for non-UNIFORM secrets (`ckksrns-fhe.cpp:888`); enabling sparse + the
     corresponding `K_SPARSE`/coefficient table is the most tractable lever. (Standard CKKS uses
     `K_SPARSE=28` vs `K_UNIFORM=512` — a `~18×` smaller overflow bound.)
   - A larger message scale / different `q0`/`Δ` ratio so the message is less dominated by `q0·I`.
   - Investigate the **conjugation-trick analogue** (§7.2): is there a two-real-channel formulation of
     CtS for CI that recovers the coefficients to std-level precision?
2. **Non-amplifying StC** (attacks effect B): an orthonormalized basis / pre-scaled coefficients so
   `StC` does not multiply the per-coefficient error by `‖U‖_∞ ≈ N`. Since `U^T U = diag(N,2N,…)`, an
   orthonormal variant `Ũ = U·diag(1/√N, 1/√2N, …)` is available; the question is threading the
   compensating scale through CtS/EvalMod/StC without breaking the `t mod q0` recovery.
3. **Higher-precision EvalMod** (orthogonal, a few bits): arcsine/minimax `Mod1` instead of the sine +
   double-angle. Useful but does not address A or B.

**Explicitly excluded per the project owner: META-BTS / iterative bootstrapping** — it masks rather
than fixes the per-bootstrap precision and is considered cheating for this goal.

## 11. Summary for the planner

- **Built:** a complete, correct, opt-in native CI CKKS scheme + bootstrap (rank `N`, no ring switch),
  with a hoisted extended-basis g=5-aligned collapsed real-DFT (correct + fast), validated to `2^-100`
  in cleartext, demonstrating `2×` packing and a `1.63×` throughput win.
- **Problem:** recovered precision is ~5–7 bits vs standard CKKS ~38 at iso-config.
- **Diagnosis (high-confidence, measured):** the floor is **not** the transform, key-switching,
  EvalMod, or encode/decode. It is intrinsic to the CI ring: **(A)** the message — spread over `N`
  coefficients by `U^{-1}` — is swamped by the ModRaise overflow inside CtS, capping coefficient
  recovery at ~16 bits; **(B)** the non-orthonormal decode `U` (`‖u_i‖²=2N`, `‖U‖_∞≈1.3N`) amplifies
  the per-coefficient error by ~`N` in StC. Standard CKKS avoids both (`N/2` complex coeffs +
  near-orthonormal FFT decode).
- **Open sub-question:** *why* CI coefficient-recovery is ~16 bits while std is ~46 (same overflow,
  comparable magnitudes) — likely the conjugation-trick / single-vs-two-real-channel difference.
- **Fix levers (structural, not software):** (1) shrink overflow-to-message ratio (sparse secret →
  smaller `‖I‖`; the CI branch currently rejects non-UNIFORM secrets), (2) non-amplifying/orthonormal
  StC, (3) arcsine/minimax EvalMod (orthogonal). **No META-BTS.**
